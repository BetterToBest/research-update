# Audit plan: two defects fixed before the release, in the studies kept as the record

Nov 26, 2026 (S103). Written and committed before any rerun below was read. The only run before this file was the timing of one seed of the price-rule pilot with the store's log on, which reads no figure (it showed which rows take another row's path, which is structure, not an outcome).

## The two defects
1. **The stored no-programme supply path** (fixed in v5.9.22; preregistration `prereg/2026-11-s90-private-price-at-sale.md`, Amendment 4). The engine stores each seed's no-programme supply path (`tbBaseS`, used by rows with `fx.sp`; `s3BaseS`, used by rows with households, income-graded spending or the line) under a key that left out five row settings: pay by household type (`eh`), the capacity price rule and its options (`pr`), bargaining (`bg`), the government account (`gv`) and PTF running costs (`po`). These are set per row (`c.pr`, `c.bg`, and so on), not through the row's options, so a row that differs from an earlier row of the same seed only in them took the earlier row's path. A row run first in its process was right.
2. **The ESP payroll pool with no wage weight** (fixed in v5.9.23; the same preregistration, Amendment 6). In a year where the ESP's payroll pool was positive and none of its workers had a wage the year before, the pool left the BU stock without being returned, converted or destroyed.

## Method
**Defect 1.** For each study, a scratch copy of its own engine commit with a reporting-only patch (`patch.py`, kept with the record): with `S103_FIX=1` the store's keys gain exactly the v5.9.22 key (`rowKeyS93`'s five settings); unset, the engine computes as before, and an optional log records every lookup that takes a path stored for different settings (row, seed, both settings). Each job is run twice, as it was run (same command, environments, seeds, one process per call): unpatched and with the fix. Checks before any comparison is read: the unpatched run reproduces the published summary in `dev/runs/` (every printed estimate); with the fix, the log is empty by construction and every row the log did not name is identical to the unpatched run on every key. Then for every reached row: the change in every preregistered outcome (fixed minus published, the study's own table tool on both runs), and whether any printed figure changes in its printed digits, in sign, or in a decision rule's verdict.

Why the study's own engine and not v5.9.22: v5.9.22 also moves the private price to the sale, so a rerun there mixes two changes. With the fix on the study's own engine the only difference is the defect. (The plan's wording, "rerun on v5.9.22 with the rows alone", is met in substance: a row run alone has its own path, which is what the fix gives every row.)

**The recession-slack reading** (`pr.rs`). Its unit test moved the year-20 price level in Adverse seed 39 only on the borrowed path. On the price-rule studies' engines with the fix, and on v5.9.23: the reading's effect on each outcome on its own path, from the fixed runs above (the rows that differ only in `rs`). If the reports state an effect of `rs` that comes only from the borrowed path, they are corrected.

**Defect 2.** The same scratch engines, with a second reporting-only patch: a count of years in which the ESP's pool is positive and the sum of its workers' last-year wages is 0 (the exact condition the v5.9.23 fix acts on; v5.9.23's tally `retNoW` counts the BU returned that way). Each study's job, seeds 1-2, every cell. A study with no such year is not reached. For a reached study: its reached rows rerun on its own engine with the v5.9.23 rule backported (the pool returned to the ESP), every seed, and the change in each outcome as above.

## What follows
- Every reached report gets a dated note (rule 2; reader text, no internal labels): what the defect was, which rows it reached, how far each figure moves, and the corrected figures where a printed figure changes. The published folders and figures stay as the record of their engine; nothing is dropped.
- A reached figure that the Hub or the findings page prints is corrected there with a dated note and a corrections-log entry.
- No constant or row changes. Nothing here changes a design (no ledger decision unless a decision rule's verdict changes, which is then recorded as a decision for Duke).
- The record: `audits/2026-11-26-s103-audit.md`, with each run's command, the patch, and the comparison files.
