## How to use it

The files in `corrections/` apply every item below at its default and are ready to upload: `ai-index.json`, `ai-manifest.json`, `research-index.json` and `llms.txt` to the `bettertobest.github.io` repository, and `index.html`, `research-summary.html` and `research-summary.md` to `research-hub`. `corrections.diff` shows every change. To leave an item out, tell the next session, or run `python3 apply_corrections.py <root clone> <research-hub clone> out --skip C05,C13`; the script stops without writing if any edit fails to match exactly once, and checks that every JSON file and JSON-LD block still parses.

Three things are yours when you push: the ontology version and date (both pages show 2.3, June 14; this package changes the ontology), the research summary's "Last Updated" date, and `research-index.json`'s top-level `dateModified`.

## Why, and the options for each decision

**C01. Octave capacity formula: symbolic base, exponent n-1.** With 2^n, Octave 1 = 2 x C_base, so the formula contradicts every table in the corpus (Octave 1 = 1,000; Octave 6 = 32,000). d11 keeps the base symbolic so each country sets it in its own currency; the exponent n-1 makes the formula match the tables. Your note on d11 named both 1,000 and 1,200; the default reads C_base as Octave 1's capacity because every table uses 1,000. Default (applied): C_n = C_base x 2^(n-1), with C_base = the Octave 1 monthly capacity each jurisdiction sets (1,000 BU in the examples). Alternative: C_base = the monthly BU allocation (1,200 in the examples), which changes every capacity table (Octave 1 = 1,200, Octave 6 = 38,400). Records: AI-c53c65ce, AI-e24140d0, AI-326b7887, AI-75f929f7, AI-eef34a71, FP-3ea3f297, FP-e823ded2. Locations found this session: research-hub/ :: JSON-LD, DefinedTerm 'Octave Levels' (line 577).

**C02. One figure for the maximum effective conversion rate (14.56x).** The index files say ~14x; the front page, llms.txt and the ontology say 14.56x (9 x 1.618). Records: AI-dfba05bf, AI-7bad2a62.

**C03. ε_food = 2.64 and the BU purchasing-power premium: an assumption, not a calibration.** Session 3 read the cited Errasti et al. (2003) in full and the main Eroski study (Arando et al. 2011): neither contains an overhead comparison or the 35–55% figure. The step from an overhead cut to prices at 0.378 of market is not stated, and 1/0.378 = 2.6455, which rounds to 2.65. For scale: the NYC public grocery pilot promises about 30% off (ε ≈ 1.43), against the 62% cut that 2.64 implies. Default (applied): Restate 2.64 as an assumed PTF food-price advantage; drop 'Mondragon-calibrated'. Alternative: Supply a primary source that states the 35–55% overhead reduction (Whyte & Whyte 1991, a book, is the one cited source not yet checked). Records: AI-ad6f76ef, AI-3032d999, AI-35e9cb99.

**C04. PTF 40–60% overhead reduction: a design target, with the unverified basis removed.** The target stays. Its stated basis, a 35–55% Mondragon/Eroski overhead reduction, was not found in the cited source (see C03). Three index entries state the reduction as a fact. Records: AI-61d88d85, AI-1a9b2a65, AI-f77face0, AI-7d853e53, AI-da50fd63, RS-50256c5e, RS-135f209c, RS-f7c4d41e.

No simulation, derivation or source supports it, and its 35–50% matches neither the front page's 35–55% basis nor the 40–60% target. Default (applied): Restate as design targets, in the target figures used elsewhere. Alternative: Delete the sentence. Records: AI-4763aff1.
